## 1. Project Overview
**Casino Royale** is a modern, web-based mock cryptocurrency gambling platform. The project is built with a minimalist, high-contrast, brutalist aesthetic (black/white, monospaced fonts, uppercase typography).

### Tech Stack
* **Framework:** Next.js 16.1.6 (App Router), React 19
* **Language:** TypeScript
* **Styling:** Tailwind CSS v4, Framer Motion (animations)
* **Icons:** Lucide React
* **Database & ORM:** PostgreSQL with Prisma Client & `@prisma/adapter-pg`
* **Authentication:** `better-auth`
* **State Management:** Zustand (Client-side global state)

## 2. What Has Been Built So Far (Architecture & Features)

### 2.1. Database Schema
The database is structured via Prisma (`prisma/schema.prisma`) and includes:
* **User System (`User`, `Session`, `Account`, `Verification`):** Standard schema customized to include a `balance` field (Float, defaults to 0).
* **Ledger System (`Transaction`):** A robust transaction model tracking `userId`, `type` (deposit, withdrawal, bet, win), `amount`, and `description`.

### 2.2. Core Logic & Libs
* **Transactions (`lib/transactions.ts`):** Contains the core financial logic. Uses Prisma's `$transaction` API to ensure ACID compliance when updating a user's balance and recording the transaction simultaneously. It prevents users from spending more than their balance on bets and withdrawals.
* **Global State (`lib/store.ts`):** A Zustand store (`useUserStore`) that easily manages fetching and providing the user's current balance across all client components.
* **Authentication (`lib/auth.ts`, `lib/auth-client.ts`):** Configuration for session management using `better-auth`.

### 2.3. User Interface & Pages
* **Landing Page (`app/page.tsx`):** A visually striking homepage with "Provably Fair," "No Limits," "Pure Chance" branding and an entry point ("Enter The Pit").
* **Layout & Navigation (`app/layout.tsx`):** Implements a `Navbar` and globally wraps the application with Geist fonts.

### 2.4. Routes & Features
* **Auth (`app/login`, `app/signup`):** Interfaces for user registration and login.
* **Banking (`app/buy`, `app/transactions`):** Routes for handling deposits and viewing transaction history.
* **Games Hub (`app/games`):** The primary directory for individual gambling games.

### 2.5. Prototype Game: "Eat Money"
Located in `app/games/eat-money`. This serves as a functional demonstration of the banking logic.
* It requires users to be authenticated.
* Features a "DO NOT CLICK" button.
* When clicked, it triggers a server action (`actions.ts` -> `eatMoney`) that attempts to deduct 1000 credits from the user.
* It safely handles transactions through the core `createTransaction` helper, ensuring validation, and triggers an immediate client-side balance update via the Zustand store on success.
